    Investigation tools¶

    The tools the EIS extension gives Claude (Spec 16 §4.2). Claude calls them; you don't need to — this page is for reading what Claude can and cannot do, and for checking a tool from the command line with slingology-eis mcp call TOOL '{…}', which prints the same JSON Claude receives.

    Every result is {engine_version, workspace_id, result}. Tools marked writes change something in the workspace (a notebook, the inbox, the workspace used for the conversation); the others only read. None reaches the internet. A refusal is an error whose text says why and what to ask instead.

    33 tools, in the order Claude sees them.

    Tool What it does
    guide How to investigate with EIS, in one document: the method (one flight first, then across the flights; the mechanism as a hypothesis; alternatives ruled out; what it means and what to do; no verdict words without their reference), the tool map with every parameter form and an example, the notebook rules, this aircraft's record and the owner's notes, its documents, and the workspace in use (flights, date span, open inbox candidates)
    workspaces_list The aircraft's workspaces (and any other aircraft's), with the one these tools use
    workspace_use writes Use another of the aircraft's workspaces for the rest of this conversation (not the EIS pages)
    flights_list The workspace's flights, oldest first: local date and start/end time with the zone, route (airports resolved from GPS), takeoffs and landings, the pilot's name, engine hours, source (G3X or AXIS), flight facts, minutes per phase and event count
    flights_find Flights for a description in words, best first (at most 10), each with what matched: dates ("Oct 24", "2026-10-24", "last Friday", a month or weekday), airports by code or name ("KBLI", "Bellingham"), counts ("three landings", "two stops", "touch and go"), words of the pilot's flight name
    flight_get One flight: header, phases, flight facts, events (limit exceedances and CAS) and the topic findings the Flight view shows
    series_get Channels of one flight over a window (seconds from the log's start)
    fleet_metrics The Spec 12 per-flight metrics table (one row per flight, ordered by engine hours) with each metric's baseline, trend, outliers and shift; 50 rows per page
    trends_summary The Trends change summary (ranked metrics with baseline, trend and shift) and the shift history.
    presets_list The engine profile's shipped slice rules (Spec 06): id, name, the question each is for, its conditions.
    slices_build The slices a selection and slice rules make, each with its local time, context and descriptors; 50 per page
    samples_get The 1 Hz samples of slices, aligned at an anchor (crossing, start, end, peak:CHANNEL)
    question_run A Spec 06 test over a slice set — cycling, coupling, groups or unusual — with its finding, magnitude with OM references, caveats and the evidence rows (50 per page)
    signal_analyze One flight's rolling strips, summarised as the runs where each channel cycles (lit), and a window's descriptors, numbers with OM references and diagnostics (periods, the 5 strongest periodogram peaks, best lag) and caveats
    rows_compare One row per slice, grouped by flight, with deltas to a pinned row; 50 rows per page
    code_run writes Run Python on the bench and keep it as a code cell in the notebook study_id (study_create first: every executed cell belongs to a notebook) — appended, or replacing cell_id
    profile_get The engine profile: limits with their Operators Manual references.
    aircraft_get The aircraft record: name, airframe, engine serial, propeller, controller, firmware, avionics, the documents folders; the owner's notes (notes.md) whole; its workspaces; the engine model and the Settings → Log channels assignments.
    documents_list The aircraft's documents — the Operators Manual, service bulletins, manuals, notes — read in place from the folders the owner named (Settings → Aircraft → Documents folders; subfolders included): name, folder, kind, pages, first line
    document_read Pages of one document (at most 3 at a time), or the pages where a phrase occurs (find: case-insensitive, accents ignored, with snippets)
    journal_list The Journal entries as the UI shows them; 50 per page.
    studies_list The studies in the workspace: kind, author, question, status, finding.
    study_read One study: a notebook's metadata (question, status, summary) and its cells with their outputs (figures named, not drawn; pending re-run outputs flagged).
    study_create writes Start an investigation notebook for a question; its first cell holds the question
    cell_append writes Append a cell to a notebook: markdown (source) — say what the next figure shows, or what a result means; code (source, run at once, as code_run); logview (flight, start_s, end_s, channels, marks [[t_s, "label"], …], title) — a strip chart of a window of one flight that the EIS pages open as the Flight view
    study_rerun writes Re-run every code cell of a notebook against this workspace; outputs that differ wait as pending until study_accept or study_discard.
    study_accept writes Accept the pending re-run outputs (all, or cell_ids): they become the cells' outputs
    study_discard writes Discard the pending re-run outputs (all, or cell_ids); the stored outputs stand
    study_finish writes End an investigation with its summary (what was found, what it means, what to do)
    inbox_list The candidates the detectors raised (recurring patterns, stand-out flights, shifts, groups) with evidence and status; scans first when there are new flights
    inbox_resolve writes Set a candidate's status — investigating, nothing-here, watch, acted (or new) — with its study and a note
    pins_list The owner's questions and marks (Mark for Claude on the Flight view): each question with its status, notebook and marks — flight, window (start_s, end_s and the local time), the channels shown, the owner's note — and the unassigned marks
    question_resolve writes Set one of the owner's questions' status — investigating, nothing-here, watch, acted (or new) — with its notebook and a note; its marks take the resolution

    guide¶

    How to investigate with EIS, in one document: the method (one flight first, then across the flights; the mechanism as a hypothesis; alternatives ruled out; what it means and what to do; no verdict words without their reference), the tool map with every parameter form and an example, the notebook rules, this aircraft's record and the owner's notes, its documents, and the workspace in use (flights, date span, open inbox candidates). Call it at the start of every conversation.

    No parameters.

    workspaces_list¶

    The aircraft's workspaces (and any other aircraft's), with the one these tools use. Usually one: the server opens the aircraft's workspace without asking.

    No parameters.

    workspace_use¶

    Writes.

    Use another of the aircraft's workspaces for the rest of this conversation (not the EIS pages). Example: {"workspace_id": "ws_2b59350ca5ac"} or the workspace's name.

    Parameter Type
    workspace_id string required

    flights_list¶

    The workspace's flights, oldest first: local date and start/end time with the zone, route (airports resolved from GPS), takeoffs and landings, the pilot's name, engine hours, source (G3X or AXIS), flight facts, minutes per phase and event count. Filters: date_from/date_to (local YYYY-MM-DD), source, airport (any airport on the route), name (words in the pilot's name or notes), hours_min/hours_max; 50 per page. Example: {"airport": "KBLI", "date_from": "2026-10-01"}.

    Parameter Type
    date_from string Local date YYYY-MM-DD
    date_to string Local date YYYY-MM-DD
    source G3X | AXIS
    airport string An airport code on the route, e.g. KBLI
    name string Words in the flight's name or notes
    hours_min number
    hours_max number
    offset integer (minimum 0) First row (default 0)
    limit integer (minimum 1, maximum 50) Rows (≤ 50)

    flights_find¶

    Flights for a description in words, best first (at most 10), each with what matched: dates ("Oct 24", "2026-10-24", "last Friday", a month or weekday), airports by code or name ("KBLI", "Bellingham"), counts ("three landings", "two stops", "touch and go"), words of the pilot's flight name. Example: {"description": "the Oct 24 flight with three landings, Bellingham"}.

    Parameter Type
    description string required
    limit integer (minimum 1, maximum 10)

    flight_get¶

    One flight: header, phases, flight facts, events (limit exceedances and CAS) and the topic findings the Flight view shows. Example: {"flight_id": "1e10d971bd5da136"}.

    Parameter Type
    flight_id string required

    series_get¶

    Channels of one flight over a window (seconds from the log's start). At most 6 channels; a window of up to 600 s comes back at every row, a longer one as a 600-point min/max envelope per channel. Without a window it answers only for a flight that short. Example: {"flight_id": "1e10d971bd5da136", "channels": ["rpm", "map_inhg"], "start_s": 600, "end_s": 660}.

    Parameter Type
    flight_id string required
    channels list of string required
    start_s number
    end_s number

    fleet_metrics¶

    The Spec 12 per-flight metrics table (one row per flight, ordered by engine hours) with each metric's baseline, trend, outliers and shift; 50 rows per page. Default metrics: all but the limit_* ones. Example: {"metrics": ["cht_max_f", "oil_temp_max_f"], "limit": 20}.

    Parameter Type
    metrics list of string
    flights list of string
    offset integer (minimum 0) First row (default 0)
    limit integer (minimum 1, maximum 50) Rows (≤ 50)

    trends_summary¶

    The Trends change summary (ranked metrics with baseline, trend and shift) and the shift history.

    No parameters.

    presets_list¶

    The engine profile's shipped slice rules (Spec 06): id, name, the question each is for, its conditions.

    No parameters.

    slices_build¶

    The slices a selection and slice rules make, each with its local time, context and descriptors; 50 per page. A slice set: flights (default every flight) and slice_rules, each a preset id ("full_power"), a phase ("phase:CLIMB") or a rule object ({"rule_id": "high_map", "name": "MAP >= 38", "conditions": [{"channel": "map_inhg", "op": ">=", "value": 38}], "min_duration_s": 20}); optional hand_slices ([{"flight": "…", "start_s": 600, "end_s": 660}]) and windows ({"rpm": {"window_s": 8, "lag_s": 5}}). Example: {"slice_rules": ["full_power"], "channels": ["rpm", "map_inhg"]}.

    Parameter Type
    slice_rules list of string or object Slice rules: a preset id (presets_list), "phase:CLIMB", or a Spec 06 §5.1 rule object
    hand_slices list of object Hand slices:
    flights list of string Flight ids (default: every flight)
    channels list of string Channels (default rpm, map_inhg)
    windows object Per channel {window_s, lag_s} (default: the engine's)
    offset integer (minimum 0) First row (default 0)
    limit integer (minimum 1, maximum 50) Rows (≤ 50)

    samples_get¶

    The 1 Hz samples of slices, aligned at an anchor (crossing, start, end, peak:CHANNEL). Refuses more than 6000 values — name slice_ids from slices_build. A slice set: flights (default every flight) and slice_rules, each a preset id ("full_power"), a phase ("phase:CLIMB") or a rule object ({"rule_id": "high_map", "name": "MAP >= 38", "conditions": [{"channel": "map_inhg", "op": ">=", "value": 38}], "min_duration_s": 20}); optional hand_slices ([{"flight": "…", "start_s": 600, "end_s": 660}]) and windows ({"rpm": {"window_s": 8, "lag_s": 5}}). Example: {"slice_rules": ["full_power"], "slice_ids": [""], "channels": ["rpm"], "anchor": "start"}.

    Parameter Type
    slice_rules list of string or object Slice rules: a preset id (presets_list), "phase:CLIMB", or a Spec 06 §5.1 rule object
    hand_slices list of object Hand slices:
    flights list of string Flight ids (default: every flight)
    channels list of string Channels (default rpm, map_inhg)
    windows object Per channel {window_s, lag_s} (default: the engine's)
    slice_ids list of string
    anchor string

    question_run¶

    A Spec 06 test over a slice set — cycling, coupling, groups or unusual — with its finding, magnitude with OM references, caveats and the evidence rows (50 per page). A slice set: flights (default every flight) and slice_rules, each a preset id ("full_power"), a phase ("phase:CLIMB") or a rule object ({"rule_id": "high_map", "name": "MAP >= 38", "conditions": [{"channel": "map_inhg", "op": ">=", "value": 38}], "min_duration_s": 20}); optional hand_slices ([{"flight": "…", "start_s": 600, "end_s": 660}]) and windows ({"rpm": {"window_s": 8, "lag_s": 5}}). groups: params.descriptor is channel.measure ("rpm.swing"); params.split is "source" (short for {"by": "source"}), {"by": "date", "date": "2026-10-01"}, {"by": "da_band"}, {"by": "oat_band", "edges": [5, 20]}, {"by": "engine_hours", "edges": [150]}, {"by": "rule"} or {"by": "flights", "groups": [{"label": "before", "flights": ["…"]}, {"label": "after", "flights": ["…"]}]}. Examples: {"test_id": "cycling", "slice_rules": ["full_power"], "channels": ["rpm"]}; {"test_id": "coupling", "slice_rules": ["full_power"], "channels": ["rpm", "map_inhg"]}; {"test_id": "groups", "slice_rules": ["full_power"], "params": {"descriptor": "rpm.swing", "split": "source"}}; {"test_id": "unusual", "slice_rules": ["full_power"]}.

    Parameter Type
    test_id cycling | coupling | groups | unusual required
    params object Test parameters (Spec 06 §7)
    reference string
    slice_rules list of string or object Slice rules: a preset id (presets_list), "phase:CLIMB", or a Spec 06 §5.1 rule object
    hand_slices list of object Hand slices:
    flights list of string Flight ids (default: every flight)
    channels list of string Channels (default rpm, map_inhg)
    windows object Per channel {window_s, lag_s} (default: the engine's)
    offset integer (minimum 0) First row (default 0)
    limit integer (minimum 1, maximum 50) Rows (≤ 50)

    signal_analyze¶

    One flight's rolling strips, summarised as the runs where each channel cycles (lit), and a window's descriptors, numbers with OM references and diagnostics (periods, the 5 strongest periodogram peaks, best lag) and caveats. Without a window, the window is derived from where the reference channel cycles. skip_onset_s leaves the window's first seconds out of the descriptors and period (a power change at its start buries the cycle; a caveat suggests a value when it sees one). Example: {"flight_id": "1e10d971bd5da136", "start_s": 600, "end_s": 662, "channels": ["rpm", "map_inhg"], "skip_onset_s": 16}.

    Parameter Type
    flight_id string required
    channels list of string
    start_s number
    end_s number
    reference string
    skip_onset_s number (minimum 0) Seconds at the window's start left out of the descriptors (default 0)
    strips boolean Compute the rolling strips (default true)

    rows_compare¶

    One row per slice, grouped by flight, with deltas to a pinned row; 50 rows per page. A slice set: flights (default every flight) and slice_rules, each a preset id ("full_power"), a phase ("phase:CLIMB") or a rule object ({"rule_id": "high_map", "name": "MAP >= 38", "conditions": [{"channel": "map_inhg", "op": ">=", "value": 38}], "min_duration_s": 20}); optional hand_slices ([{"flight": "…", "start_s": 600, "end_s": 660}]) and windows ({"rpm": {"window_s": 8, "lag_s": 5}}). Example: {"slice_rules": ["full_power"], "pinned": ""}.

    Parameter Type
    slice_rules list of string or object Slice rules: a preset id (presets_list), "phase:CLIMB", or a Spec 06 §5.1 rule object
    hand_slices list of object Hand slices:
    flights list of string Flight ids (default: every flight)
    channels list of string Channels (default rpm, map_inhg)
    windows object Per channel {window_s, lag_s} (default: the engine's)
    reference string
    pinned string
    collapse boolean
    offset integer (minimum 0) First row (default 0)
    limit integer (minimum 1, maximum 50) Rows (≤ 50)

    code_run¶

    Writes.

    Run Python on the bench and keep it as a code cell in the notebook study_id (study_create first: every executed cell belongs to a notebook) — appended, or replacing cell_id. The namespace has numpy (np), pandas (pd), scipy, matplotlib (plt) and the eis library, the tools' own code: eis.flights(), eis.find("Oct 24 Bellingham"), eis.load(flight, ["rpm"], start_s, end_s), eis.slices("full_power"), eis.cycling("full_power", "rpm") → Result (.finding, .magnitude, .caveats, .rows, .figure(); print(r) is the §8 text), eis.coupling(rule, ["rpm", "map_inhg"]), eis.groups(rule, "rpm.swing", by="source") or by="date", date="2026-10-01", eis.unusual(rule), eis.signal(flight, start_s, end_s, ["rpm"]), eis.compare(rule), eis.logview(flight, start_s, end_s, ["rpm", "map_inhg"], marks=[(t_s, "label")]), eis.document("om.pdf").find("boost"), eis.aircraft, eis.profile, eis.notes. A rule is a preset id, "phase:CLIMB", a rule object or {selection, slice_rules, hand_slices}. The last expression's value is shown, as in Jupyter. No network, no subprocesses, writes only under FILES, time and memory capped. Returns stdout (≤ 8000 characters), tables (text) and up to 4 figures as images. Example: {"study_id": "…", "source": "r = eis.cycling('full_power', 'rpm')\nprint(r)"}.

    Parameter Type
    study_id string required
    source string required
    cell_id string
    timeout_s number (minimum 1, maximum 300) Default 60
    memory_mb number (minimum 256, maximum 8192) Default 2048

    profile_get¶

    The engine profile: limits with their Operators Manual references.

    No parameters.

    aircraft_get¶

    The aircraft record: name, airframe, engine serial, propeller, controller, firmware, avionics, the documents folders; the owner's notes (notes.md) whole; its workspaces; the engine model and the Settings → Log channels assignments.

    No parameters.

    documents_list¶

    The aircraft's documents — the Operators Manual, service bulletins, manuals, notes — read in place from the folders the owner named (Settings → Aircraft → Documents folders; subfolders included): name, folder, kind, pages, first line. With no folder set it says so.

    No parameters.

    document_read¶

    Pages of one document (at most 3 at a time), or the pages where a phrase occurs (find: case-insensitive, accents ignored, with snippets). Never a whole manual. Examples: {"name": "Bulletins/APL-SB-23.pdf", "find": "hunting"}, {"name": "om.md", "page": 5, "pages": 2}.

    Parameter Type
    name string required
    page integer (minimum 1)
    pages integer (minimum 1, maximum 3)
    find string

    journal_list¶

    The Journal entries as the UI shows them; 50 per page.

    Parameter Type
    offset integer (minimum 0) First row (default 0)
    limit integer (minimum 1, maximum 50) Rows (≤ 50)

    studies_list¶

    The studies in the workspace: kind, author, question, status, finding.

    No parameters.

    study_read¶

    One study: a notebook's metadata (question, status, summary) and its cells with their outputs (figures named, not drawn; pending re-run outputs flagged).

    Parameter Type
    study_id string required

    study_create¶

    Writes.

    Start an investigation notebook for a question; its first cell holds the question. Add cells with cell_append and code_run, end with study_finish. With question_id (one of the owner's questions, pins_list) the notebook opens with the owner's marks: each mark's note, then a log view of its window. Example: {"name": "Full-power rpm cycling", "question": "Why does rpm hunt at full power?"}, or {"name": "Rough climbs", "question_id": "q-1a2b3c4d"}.

    Parameter Type
    name string required
    question string
    kind investigation | question-for-type
    inbox_candidate string The inbox candidate this investigates (marked investigating)
    question_id string The owner's question this takes up (pins_list): marked investigating, and a markdown cell with each mark's note followed by its log view
    engine_type string

    cell_append¶

    Writes.

    Append a cell to a notebook: markdown (source) — say what the next figure shows, or what a result means; code (source, run at once, as code_run); logview (flight, start_s, end_s, channels, marks [[t_s, "label"], …], title) — a strip chart of a window of one flight that the EIS pages open as the Flight view. Example: {"kind": "logview", "flight": "…", "start_s": 360, "end_s": 420, "channels": ["rpm", "map_inhg"], "marks": [[367, "takeoff power"]]}.

    Parameter Type
    study_id string required
    kind markdown | code | logview required
    source string
    role string
    flight string
    start_s number
    end_s number
    channels list of string
    marks list of list of values
    title string
    rule string
    timeout_s number
    memory_mb number

    study_rerun¶

    Writes.

    Re-run every code cell of a notebook against this workspace; outputs that differ wait as pending until study_accept or study_discard.

    Parameter Type
    study_id string required

    study_accept¶

    Writes.

    Accept the pending re-run outputs (all, or cell_ids): they become the cells' outputs. With source "external": accept instead the outputs a kernel outside EIS (JupyterLab) saved in the notebook, as they stand (cells marked ran elsewhere). Example: {"study_id": "…", "cell_ids": ["c6"]}.

    Parameter Type
    study_id string required
    cell_ids list of string
    source rerun | external rerun (default): the bench's pending outputs; external: outputs saved outside EIS

    study_discard¶

    Writes.

    Discard the pending re-run outputs (all, or cell_ids); the stored outputs stand. Example: {"study_id": "…", "cell_ids": ["c6"]}.

    Parameter Type
    study_id string required
    cell_ids list of string

    study_finish¶

    Writes.

    End an investigation with its summary (what was found, what it means, what to do). Refused while a figure or log view has no markdown cell right before or after it (the answer names the cells). Optionally resolves its inbox candidate, resolves the owner's question it answered (question; with its marks; resolution defaults to watch for a question) and notes the finding in the Journal (the one Journal entry Claude may write). Reports the flights the cells read and the inbox's open candidates. Example: {"study_id": "…", "summary": "…", "question": "q-1a2b3c4d", "resolution": "watch", "journal": true}.

    Parameter Type
    study_id string required
    summary string required
    inbox_candidate string
    question string The owner's question this answers (pins_list); it and its marks take the resolution
    resolution investigating | nothing-here | watch | acted
    note string
    journal boolean
    finding string

    inbox_list¶

    The candidates the detectors raised (recurring patterns, stand-out flights, shifts, groups) with evidence and status; scans first when there are new flights. Example: {"status": ["new", "investigating"]}.

    Parameter Type
    status string or list of string

    inbox_resolve¶

    Writes.

    Set a candidate's status — investigating, nothing-here, watch, acted (or new) — with its study and a note. Example: {"candidate_id": "…", "status": "nothing-here", "note": "the governor, known"}.

    Parameter Type
    candidate_id string required
    status new | investigating | nothing-here | watch | acted required
    study_id string
    note string

    pins_list¶

    The owner's questions and marks (Mark for Claude on the Flight view): each question with its status, notebook and marks — flight, window (start_s, end_s and the local time), the channels shown, the owner's note — and the unassigned marks. A mark is where to look and a sentence, not a finding. newest_open names the question to take up when the owner asks without saying which. Example: {"status": ["new", "investigating"]}.

    Parameter Type
    status string or list of string

    question_resolve¶

    Writes.

    Set one of the owner's questions' status — investigating, nothing-here, watch, acted (or new) — with its notebook and a note; its marks take the resolution. study_finish with question does this as it ends a notebook. Example: {"question_id": "q-1a2b3c4d", "status": "watch", "study_id": "st-…"}.

    Parameter Type
    question_id string required
    status new | investigating | nothing-here | watch | acted required
    study_id string
    note string
